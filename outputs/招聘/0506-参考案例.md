# 参考案例 / Bar 在哪

## 给应聘者的话(回我前先看)

我**不需要**你看完所有。看 30 分钟就够。

回我的时候挑 2-3 个站,告诉我:
1. **为什么好** —— 不要"卧槽 NB",说出来好在哪(技术、视觉、节奏哪一项)
2. **你会怎么复刻** —— 大概的栈选型 + 关键技术点(比如 "lenis + GSAP ScrollTrigger 控制相机推进,R3F 加载 GLB 模型,drei 的 Float 做 idle 浮动")
3. **你的差距** —— 哪一类你做过 / 哪一类没做过

第 3 条很关键 —— 我**不要**那种"看到任何参考都说自己能做"的人。能诚实说"R3F 我没碰过,Framer Motion + GSAP 没问题"的,反而加分。

## 项目方栏(发帖人自留 — 不要发给应聘者)

### 这份案例怎么用

- **私信场景**:对方第一条回复后,直接发这份(URL 或 PDF 截图)。让对方在 24h 内挑 2-3 个回。
- **筛选信号**:
  - 回得快 + 答得有结构 → 进 30 分钟试聊
  - 只夸不分析 / 抄维基百科式答案 → pass
  - 挑了 D 类(独立开发) + 答得有 own 感 → 优先
  - 挑了 C 类(3D/WebGL) + 自称做过 → 试聊时可以加一题问 R3F 心智模型,容易识别水分
- **不要透露项目** —— 第 3 段写"项目栈大概是..."就到边了。具体方向 / 名字 / Web3 属性都不能在这份文档里出现,正式签 NDA 后再说。

### 维护

- 案例如果某个站改版变烂了,及时换。建议每 3 个月扫一遍 URL 还在 + 内容还代表"好"。
- 加分类(C / D / E)可以按候选人具体兴趣灵活补。比如对方做过游戏 UI,加 `playstation.com` / `riotgames.com`;对方做过 fintech,加 `mercury.com` / `ramp.com`。
